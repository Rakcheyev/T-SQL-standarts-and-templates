# Нотатки по PostgreSQL (T‑SQL ↔ PG)

Цей репозиторій має **production‑фокус на SQL Server / T‑SQL**, але багато патернів переносимі.
Ця сторінка — короткий перекладач “та сама ідея, інший синтаксис/інструменти”.

## 1) `APPLY` ↔ `LATERAL`

**Концепт:** виконати підзапит “на кожен рядок зліва”.

- SQL Server:
  - `CROSS APPLY` ≈ inner‑семантика
  - `OUTER APPLY` ≈ left‑семантика
- PostgreSQL:
  - `CROSS JOIN LATERAL` ≈ inner‑семантика
  - `LEFT JOIN LATERAL ... ON true` ≈ left‑семантика

Приклад (top‑1 замовлення на клієнта):

SQL Server (T‑SQL):
```sql
SELECT c.CustomerID, x.OrderID, x.OrderDateTime
FROM dbo.Customers AS c
OUTER APPLY (
  SELECT TOP (1) o.OrderID, o.OrderDateTime
  FROM dbo.Orders AS o
  WHERE o.CustomerID = c.CustomerID
  ORDER BY o.OrderDateTime DESC, o.OrderID DESC
) AS x;
```

PostgreSQL:
```sql
SELECT c.customer_id, x.order_id, x.order_datetime
FROM customers AS c
LEFT JOIN LATERAL (
  SELECT o.order_id, o.order_datetime
  FROM orders AS o
  WHERE o.customer_id = c.customer_id
  ORDER BY o.order_datetime DESC, o.order_id DESC
  LIMIT 1
) AS x ON true;
```

Примітка: window functions часто є крос‑DB альтернативою для top‑N‑per‑group.

## 2) `PIVOT` / `UNPIVOT` ↔ умовна агрегація / `crosstab`

У SQL Server є `PIVOT` / `UNPIVOT`. У PostgreSQL зазвичай використовують:

- умовну агрегацію через `CASE` (переносимо)
- умовну агрегацію через `FILTER` (PG‑специфічно, дуже читабельно)
- опційно `crosstab()` з extension `tablefunc`, коли справді потрібен pivot

Приклад (два фіксовані канали):

PostgreSQL стиль `FILTER`:
```sql
SELECT
  date_trunc('month', sale_date)::date AS sales_month,
  SUM(amount) FILTER (WHERE channel = 'web') AS web_revenue,
  SUM(amount) FILTER (WHERE channel = 'store') AS store_revenue,
  SUM(amount) AS total_revenue
FROM sales
GROUP BY 1
ORDER BY 1;
```

## 3) Filtered index ↔ partial index

- SQL Server: filtered index
- PostgreSQL: partial index

Приклад у PostgreSQL:
```sql
CREATE INDEX ix_orders_paid_only
ON orders(customer_id, order_datetime DESC)
WHERE status = 'PAID';
```

## 4) Computed column + index ↔ generated column + index

- SQL Server: computed column (опційно `PERSISTED`), можна індексувати.
- PostgreSQL: generated column (`GENERATED ALWAYS AS (...) STORED`), можна індексувати.

Приклад у PostgreSQL:
```sql
ALTER TABLE events
ADD COLUMN event_day date GENERATED ALWAYS AS (event_time::date) STORED;

CREATE INDEX ix_events_event_day ON events(event_day);
```

## 5) Query Store ↔ `pg_stat_statements` + `auto_explain`

**Мета:** збирати історію запитів, бачити регресії, аналізувати плани.

- SQL Server: Query Store
- PostgreSQL:
  - `pg_stat_statements`: агрегована статистика по “нормалізованих” запитах
  - `auto_explain`: автоматичне логування планів для повільних запитів

## 6) `IDENTITY` ↔ `GENERATED AS IDENTITY`

- SQL Server: `IDENTITY(1,1)`
- PostgreSQL: `GENERATED {ALWAYS | BY DEFAULT} AS IDENTITY`

Приклад у PostgreSQL:
```sql
CREATE TABLE customers(
  customer_id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  customer_name text NOT NULL
);
```
