# PostgreSQL cross-notes (T‑SQL ↔ PG)

This repo is written with a **SQL Server / T‑SQL production focus**, but many patterns are portable.
This page summarizes common “same idea, different syntax/tooling” translations.

## 1) `APPLY` ↔ `LATERAL`

**Concept:** evaluate a subquery per left-row.

- SQL Server:
  - `CROSS APPLY` ≈ inner semantics
  - `OUTER APPLY` ≈ left semantics
- PostgreSQL:
  - `CROSS JOIN LATERAL` ≈ inner semantics
  - `LEFT JOIN LATERAL ... ON true` ≈ left semantics

Example (top-1 order per customer):

SQL Server (T‑SQL):
```sql
SELECT c.CustomerID, x.OrderID, x.OrderDateTime
FROM dbo.Customers AS c
OUTER APPLY (
  SELECT TOP (1) o.OrderID, o.OrderDateTime
  FROM dbo.Orders AS o
  WHERE o.CustomerID = c.CustomerID
  ORDER BY o.OrderDateTime DESC, o.OrderID DESC
) AS x;
```

PostgreSQL:
```sql
SELECT c.customer_id, x.order_id, x.order_datetime
FROM customers AS c
LEFT JOIN LATERAL (
  SELECT o.order_id, o.order_datetime
  FROM orders AS o
  WHERE o.customer_id = c.customer_id
  ORDER BY o.order_datetime DESC, o.order_id DESC
  LIMIT 1
) AS x ON true;
```

Note: window functions are often a great cross-DB alternative for top-N-per-group.

## 2) `PIVOT` / `UNPIVOT` ↔ conditional aggregation / `crosstab`

SQL Server has `PIVOT` / `UNPIVOT`. PostgreSQL usually uses:

- conditional aggregation with `CASE` (portable)
- conditional aggregation with `FILTER` (PostgreSQL-specific, very readable)
- optional `crosstab()` from the `tablefunc` extension when you truly need dynamic pivoting

Example (two fixed channels):

PostgreSQL `FILTER` style:
```sql
SELECT
  date_trunc('month', sale_date)::date AS sales_month,
  SUM(amount) FILTER (WHERE channel = 'web') AS web_revenue,
  SUM(amount) FILTER (WHERE channel = 'store') AS store_revenue,
  SUM(amount) AS total_revenue
FROM sales
GROUP BY 1
ORDER BY 1;
```

## 3) Filtered index ↔ partial index

- SQL Server: filtered index
- PostgreSQL: partial index

PostgreSQL example:
```sql
CREATE INDEX ix_orders_paid_only
ON orders(customer_id, order_datetime DESC)
WHERE status = 'PAID';
```

## 4) Computed column + index ↔ generated column + index

- SQL Server: computed column, optionally `PERSISTED`, can be indexed.
- PostgreSQL: generated column (`GENERATED ALWAYS AS (...) STORED`) can be indexed.

PostgreSQL example:
```sql
ALTER TABLE events
ADD COLUMN event_day date GENERATED ALWAYS AS (event_time::date) STORED;

CREATE INDEX ix_events_event_day ON events(event_day);
```

## 5) Query Store ↔ `pg_stat_statements` + `auto_explain`

**Purpose:** capture query history, observe regressions, and inspect plans.

- SQL Server: Query Store (built-in)
- PostgreSQL:
  - `pg_stat_statements`: aggregated stats per normalized query
  - `auto_explain`: automatic plan logging for slow queries

## 6) `IDENTITY` ↔ `GENERATED AS IDENTITY`

- SQL Server: `IDENTITY(1,1)`
- PostgreSQL: `GENERATED {ALWAYS | BY DEFAULT} AS IDENTITY`

PostgreSQL example:
```sql
CREATE TABLE customers(
  customer_id int GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  customer_name text NOT NULL
);
```
